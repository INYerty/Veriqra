## Root Cause

The previous WAR referenced first-party CSS and JavaScript through stable, unversioned paths. Both translation catalogs were also fetched using stable URLs. A cached resource could therefore survive a deployment even when its contents changed.

Direct requests to the isolated baseline WAR confirmed that HTML, CSS, JavaScript, and JSON had `ETag` / `Last-Modified`, but no explicit `Cache-Control` lifetime. HTML could retain old resource references through heuristic caching. These observations explain the reported symptom; production was not contacted during this task.

## Chosen Cache-Busting Design

Maven generates versioned copies of the existing HTML at build time. The source HTML remains unchanged. First-party resource references receive `?v=<token>`, and the WAR packages those generated copies.

The existing synchronous `locale-bootstrap.js` reads the token from its own script URL and publishes a small, frozen `VeriqraAssets` helper. The i18n loader uses this helper for both catalog fetches and its exposed `resourceUrl()` method. No version API, frontend bundler, additional Git detector, inline script, or filename rewrite was introduced.

Generated HTML is recreated on every build, preventing stale generated files from an earlier build from entering the WAR. References with existing query strings retain them and receive an HTML-escaped `&amp;v=` before their fragment.

## HTML Cache Behavior

The application configures Tomcat's existing `ExpiresFilter` in `web.xml`, scoped to the DefaultServlet and `REQUEST` dispatches. HTML uses `access plus 0 seconds`, producing `Cache-Control: max-age=0` and an immediately expired `Expires` value. Validators remain available, so ordinary navigation can revalidate HTML rather than retaining old asset references.

Both welcome-document URLs and direct login/index/Admin HTML requests were verified. The API servlet is outside this mapping; its existing `Cache-Control: no-store` is unchanged.

## CSS / JS Behavior

DefaultServlet CSS and JavaScript use `access plus 1 hour`. JSON served as a static resource uses the same policy. Actual responses reported `max-age=3599` or `3600`, depending on response-time rounding, with `ETag` and `Last-Modified`. Conditional requests returned 304.

Same-build URLs remain stable and can be served from the browser cache. A changed token creates a new cache key. These query-versioned paths are not an archive of immutable historical resource bytes, so no `immutable` or year-long lifetime is claimed.

## i18n Behavior

`VeriqraAssets.url()` is the single runtime URL helper. It preserves query parameters and fragments, replaces an existing `v` parameter, and only versions same-origin resources inside the application context and the first-party allowlist.

Both `en.json` and `zh-CN.json` receive the same build token. Existing catalog reuse within a page, locale selection, synchronous bootstrap, and pending-content masking remain intact. Node tests cover locale success/failure paths and no-flash behavior; real browser checks confirmed the updated Chinese text and the English switch.
