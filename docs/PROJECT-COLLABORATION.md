# 项目协作权限、小组与任务

本增量只实现项目内授权、已有账号加入项目、小组成员关系及任务指派/验收。它不实现 AI 用例生成、Credit 转账、任务奖励或月度评优，也不修改冻结的 19 张 V1 业务表。生产或日常开发数据库不会由应用自动迁移。

## 授权边界

平台 `ADMIN/USER` 仍用于账号、密码重置和项目创建等平台管理。`TESTER/DEVELOPER` 仍是每项目的专业身份。新增 `project_managers` 是独立的项目内任命关系，不写入 `users.system_role`，因此一人在不同项目可担任不同职责。`project_teams.lead_user_id` 指定具体小组负责人；组长必须同时是该组有效成员。被停用的用户、项目成员或组员不能继续使用相关权限。

| 操作 | 平台 ADMIN | 项目负责人 | 本组负责人 | 普通项目成员 |
| --- | --- | --- | --- | --- |
| 创建平台用户、重置他人密码、创建项目 | 允许 | 禁止 | 禁止 | 禁止 |
| 任命/撤销项目负责人 | 允许 | 禁止 | 禁止 | 禁止 |
| 添加已有平台账号到项目 | 允许 | 仅负责项目 | 禁止 | 禁止 |
| 建组、更换组长 | 必须另获项目负责人任命 | 仅负责项目 | 禁止 | 禁止 |
| 增减小组成员、指派/重新指派任务 | 必须另获项目内职责 | 项目内小组 | 本组 | 禁止 |
| 开始/提交任务 | 若是任务执行人 | 若是任务执行人 | 若是任务执行人 | 若是任务执行人 |
| 验收/退回任务 | 必须另获项目内职责 | 负责项目 | 本组 | 禁止 |

验收人不得是任务执行人。项目负责人可从当前项目的有效成员中指定小组负责人；小组负责人可从同一项目的有效成员中拉入本组，但不能建立平台账号或提升平台权限。平台 ADMIN 对既有测试资产的历史权限规则未在本增量中重写；上表的项目协作权限采用更窄的边界。

## 数据与事务

- `project_managers`：项目 × 用户任命及 ACTIVE/INACTIVE 状态；用户必须已有该项目成员行。
- `project_teams`：项目内唯一组名、单一组长、状态和乐观锁版本。
- `team_members`：组员关系；复合 FK 同时约束小组项目与成员项目相同。
- `work_tasks`：项目任务、所属小组、执行人、当前状态、验收人与乐观锁版本。复合 FK 阻止跨项目小组/执行人关联。
- `work_task_events`：追加式状态与指派历史，不提供普通更新/删除接口。

任务状态链为 `OPEN → IN_PROGRESS → SUBMITTED → ACCEPTED`；已提交的任务可由独立验收人填写理由退回 `IN_PROGRESS`。`OPEN/IN_PROGRESS` 可由负责人取消或重新指派。已验收和已取消任务不会被覆盖。团队组长必须是有效组员、用户/成员必须仍为 ACTIVE、任务执行人必须为有效组员、负责人不得自验等跨表规则由 Service 在事务中检查。相关写入统一按 Project → Team → Task 锁定，并由外层事务提交或回滚。

## API 与界面

所有新接口位于 `/api/projects/{projectId}` 下：`/managers`、`/members`、`/teams`、`/teams/{teamId}/members`、`/teams/{teamId}/lead`、`/tasks`、`/tasks/{taskId}`、`/tasks/{taskId}/assignee`、`/tasks/{taskId}/status`。Servlet 只解析 HTTP，Service 重新读取数据库授权信息，DAO 不提交事务。主工作区新增“小组与任务”入口，只有平台 ADMIN 能看到任命控件，项目负责人和组长按范围看到可执行操作；隐藏按钮不替代后端授权。

## 迁移与验证

空库执行 `database/schema.sql` 可建 29 表；已经是 24 表的环境必须先备份并审查，再由 DDL 管理员在**明确选定的数据库**执行 `database/migrations/20260926-collaboration.sql`。脚本不含 `CREATE DATABASE`、`USE` 或 `IF NOT EXISTS`，不适合失败后盲目重跑。迁移不会自动任命已有项目负责人；平台 ADMIN 应从有效项目成员中显式任命。应用运行用户只需现有 `veriqra.*` 的 DML 权限，不需要 DDL。

本地隔离 MySQL 8.0.46 验证了 24→29 表迁移；集成测试覆盖管理授权、组长范围、真实 HTTP 调用、跨项目 FK、任务状态/历史、独立验收和旧版本冲突。测试库与开发/生产库隔离，最后应保持 0 表并关闭临时实例。
